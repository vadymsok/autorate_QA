# План тестування вебсервісу «АвтоРейт» (Спринт 2)

## 1. Продукт і межі тестування

**Об'єкт тестування:**  
Вебсервіс «АвтоРейт» (публічний каталог і рейтинг автомобілів на базі Buggy Cars Rating)[cite: 22, 28].  
* Стек: SPA (React.js), REST API (Node.js/NestJS), NoSQL БД (MongoDB)[cite: 28, 30].

**Межі тестування (In Scope):**
* Модуль автентифікації та реєстрації користувачів (валідація, сесії, лічильник помилок).
* Модуль голосування за моделі автомобілів (оцінки 1..5, коментарі до 200 символів, захист від повторного голосування).
* Модуль розрахунку рейтингу («Рейтинг тижня», зважені оцінки за репутацією, tie-break сортування за алфавітом).
* Модуль модерації відгуків (фільтр стоп-слів, статуси модерації, права доступу).
* Каталог та пошук автомобілів за маркою та моделлю.

**Поза межами тестування (Out of Scope):**
* Внутрішня інфраструктура хмарного провайдера та дата-центру хостингу.
* Пряме тестування сторонніх бібліотек без інтеграції з кодом платформи.

## 3. Інструменти, середовище та тестові дані

* **Браузери для перевірки UI:** Google Chrome (версія 125+), Mozilla Firefox, Apple Safari, Microsoft Edge[cite: 28, 29].
* **Інструменти тестування API та безпеки:** Postman (для ручного тестування ендпоінтів), OWASP ZAP (сканування вразливостей)[cite: 27, 29].
* **Інструменти навантаження:** Apache JMeter, k6[cite: 29].
* **СУБД та інспекція даних:** MongoDB Compass (прямий контроль за колекціями `users`, `cars`, `votes`).
* **Тестові облікові записи:**
  * Тестовий гість (без авторизації);
  * Звичайний користувач: `user_test1` (репутація = 1, історія голосів порожня);
  * Досвідчений користувач: `user_senior` (репутація = 3, вже проголосував за 5 моделей);
  * Модератор: `mod_secure` (доступ до модераційної черги коментарів).

## 4. Ризики та заходи щодо їх зниження

1. **Ризик:** Порушення цілісності рейтингу при конкурентних запитах (накрутка через Race Condition)[cite: 29, 30].  
   * **Захід:** Обов'язкове проведення тестів типу 12 (Race condition) на рівні API з перевіркою атомарних блокувань у БД (MongoDB unique indexes)[cite: 29, 30].
2. **Ризик:** Зависання сторінки топу тижня через неоптимізований агрегаційний запит MongoDB при рості бази відгуків[cite: 28, 29].  
   * **Захід:** Проведення навантажувального тестування (Load/Stress) з тестовим датасетом у $\ge 5000$ записів голосів[cite: 28].
3. **Ризик:** Пропуск критичних дефектів валідації через зміни вимог у специфікації SRS 1.1[cite: 22, 26].  
   * **Захід:** Регулярне оновлення матриці простежуваності тест-кейсів до ID вимог (F-xx, BL-xx, GUI-xx)[cite: 22, 24].
