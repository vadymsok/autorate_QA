# Протокол ретроспективи Спринту 2

* **Дата проведення:** Кінець Спринту 2
* **Учасники:** Литвиненко Артем (KT), Соколов Вадим (TA), Томашук Дмитро (IT), Тарасюк Арсен (SM)
* **Фасилітатор:** Тарасюк Арсен
* **Формат:** Start / Stop / Continue

---

## 1. Start (Почати робити)
* Завчасно домовлятися про формат спільних таблиць перед початком аудиту, щоб не витрачати час на конвертацію структур даних під час зведення реєстру дефектів.
* Формулювати точний варіант виправлення («Стало») одразу в момент фіксації дефекту в чорновику, а не під час підсумкового складання SRS 1.1.
* Одразу додавати перехресні посилання між пунктами тест-плану та відповідними номерами вимог F-xx / BL-xx.

---

## 2. Stop (Припинити робити)
* Припинити завантажувати бінарні файли з дублюванням розширень (виправлено інцидент із подвійним `.xlsx.xlsx` у репозиторії).
* Не відкладати внутрішнє перехресне рецензування артефактів на останній день перед закриттям спринту.
* Уникати загальних формулювань у зауваженнях до тест-плану без зазначення конкретних кроків чи інструментів (наприклад, JMeter, Postman, Selenium).

---

## 3. Continue (Продовжувати робити)
* Зберігати практику паралельного аудиту кожного розділу специфікації мінімум двома незалежними учасниками (дозволило знайти закладені приховані суперечності в бізнес-правилах).
* Застосовувати роль «адвоката замовника» під час перевірки дефектів для відсіювання суб'єктивних побажань і збереження бізнес-логіки системи.
* Дотримуватися чіткої структури папок згідно з регламентом курсу (`docs/sprintX/`).
