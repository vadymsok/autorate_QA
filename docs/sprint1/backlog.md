# Беклог продукту «АвтоРейт» (Спринт 1)

## 1. Таблиця User Stories (12 історій користувача)

| ID | Роль | Бажання (я хочу...) | Мета (щоб...) | Пріоритет | Критерії приймання та примітки для тестування (Acceptance Criteria / Boundary Conditions) |
|---|---|---|---|---|---|
| **US-01** | Зареєстрований користувач | переглядати в особистому кабінеті історію своїх голосів | відстежувати власну активність та зміну рейтингів обраних авто | High | Відображаються дата, назва марки і моделі, виставлена оцінка (1..5) та текст коментаря; сортування за датою спаданням. При відсутності голосів — повідомлення "Ви ще не голосували". |
| **US-02** | Зареєстрований користувач | редагувати дані свого профілю (вік, стать, хобі) | тримати інформацію актуальною | Medium | Поле «Вік» приймає лише додатні цілі числа (1..120); хобі обирається зі списку. Збереження без змін неактивне. При некоректному віці — помилка валідації. |
| **US-03** | Зареєстрований користувач | змінювати пароль в особистому кабінеті | гарантувати безпеку свого облікового запису | High | Потрібно ввести поточний пароль; новий пароль має відповідати вимогам складності (≥8 символів, цифра, спецсимвол) та збігатися з підтвердженням. Старий і новий паролі не можуть бути однаковими. |
| **US-04** | Відвідувач | бачити на головній сторінці окремий блок «Рейтинг тижня» | швидко дізнаватися про топ моделей за актуальними чесними оцінками | High | До розрахунку рейтингу тижня потрапляють лише моделі з кількістю голосів ≥ 5 за поточний тиждень (BL-20); розрахунок середнього з урахуванням вагових коефіцієнтів (BL-10). |
| **US-05** | Відвідувач | бачити впорядкування за алфавітом при однаковому рейтингу моделей | мати однозначний та прозорий список топу | Medium | При рівності середнього бала порядок визначається за назвою (Марка + Модель) за зростанням (A-Z, А-Я), без урахування регістру. Список не містить дублікатів. |
| **US-06** | Зареєстрований користувач | отримувати попередження при спробі повторного голосування за ту саму модель | розуміти, чому повторний голос не зараховується | High | За одну модель користувач може проголосувати лише один раз. Після успішного голосування кнопка «Vote!» деактивується; примусовий повторний POST-запит повертає помилку 409 Conflict або повідомлення про повтор. |
| **US-07** | Зареєстрований користувач | ставити оцінку автомобілю строго від 1 до 5 | передавати коректні числові бали для підрахунку рейтингу | High | Дозволені виключно цілі значення {1, 2, 3, 4, 5}. Значення 0, 6, дробові числа, спецсимволи або порожні значення блокуються клієнтською та серверною валідацією з помилкою «Оцінка поза межами 1..5». |
| **US-08** | Зареєстрований користувач | залишати необов'язковий текстовий коментар довжиною до 200 символів | лаконічно аргументувати свою оцінку моделі | High | Граничні значення: 0 символів (дозволено), 199 і 200 символів (дозволено), 201 символ (блокується з повідомленням "Коментар задовгий, ліміт 200 символів"). XSS-ін'єкції мають екрануватися. |
| **US-09** | Відвідувач | шукати автомобілі за початком назви марки або моделі | швидко знаходити потрібну машину без повного введення назви | High | Пошук за префіксом (case-insensitive). Порожній запит повертає порожній результат або дефолтний каталог. Спеціальні символи очищуються. |
| **US-10** | Відвідувач | сортувати результати пошуку та каталогу за рейтингом | бачити спочатку авто з найвищою середньою оцінкою | Medium | Сортування за спаданням рейтингу (від 5.0 до 1.0). Вихідний масив даних не мутує, перемикання сортування не скидає введений пошуковий фільтр. |
| **US-11** | Модератор | бачити рівень репутації користувача (1..3) поруч із його коментарем | швидко оцінювати авторитетність та надійність автора відгуку | High | Репутація приймає цілі значення 1, 2 або 3; виводиться бейджем біля логіна. Відображення перевіряється для всіх трьох допустимих рівнів. |
| **US-12** | Модератор | мати автоматичне відхилення коментарів зі стоп-словами | не витрачати час на ручне видалення типового спаму | High | Стоп-слова: «spam», «scam», «casino», «казино». Перевірка без урахування регістру (case-insensitive) та часткового входження. Статус коментаря змінюється на REJECTED з поміткою «недопустиме слово». |

## 2. Матриця трасування (Traceability Matrix: Очікування замовника -> User Stories)

Прив'язка історій до 6 пунктів замовлення на нову функціональність (Каталог вимог, п. 7.4):

| № пункту замовлення | Опис вимоги з розділу 7.4 | Покриття User Stories | Примітки / реалізація |
|---|---|---|---|
| **REQ-01** | Особистий кабінет: перегляд профілю, історія власних голосів | **US-01, US-02** | Покриває відображення переліку оцінених моделей, деталей голосу та редагування особистих даних |
| **REQ-02** | Особистий кабінет: зміна пароля користувача | **US-03** | Покриває форму зміни пароля, валідацію старого пароля та вимоги безпеки нового |
| **REQ-03** | Рейтинг тижня: розрахунок за формулою та фільтр за датою | **US-04** | Покриває бізнес-правила BL-10 (вагові коефіцієнти) та BL-20 (поріг голосів ≥ 5 за тиждень) |
| **REQ-04** | Рейтинг тижня: тай-брейк за алфавітом при однаковому балі | **US-05** | Покриває логіку однозначного детермінованого сортування при збігу середніх оцінок |
| **REQ-05** | Правила голосування: один голос за модель, діапазон 1..5, коментар ≤ 200 | **US-06, US-07, US-08** | Покриває бізнес-правила валідації голосів (BL-01, BL-02, BL-03) |
| **REQ-06** | Пошук, сортування та модерація (репутація 1..3, стоп-слова) | **US-09, US-10, US-11, US-12** | Покриває UX відвідувача у каталозі та правила попередньої/автоматичної модерації відгуків |
